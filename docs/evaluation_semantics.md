# SQL执行评估口径

本模块是项目历史执行评估逻辑的提取版，不是Spider官方评估实现。

## 接口

evaluate_answer(db_path, solution_str, gold_sql)

数据库文件路径显式传入，不依赖服务器绝对路径或SPIDER_ROOT.txt。
它不是完整的verl Reward Manager入口，也不负责db_id解析。

## 保留的语义

- 最终答案提取支持FINAL_SQL、SQL代码块和直接SQL。
- 无ORDER BY时按结果行多重集合比较，保留重复次数。
- 有ORDER BY时按行序列比较；ORDER BY由正则判断。
- 比较列数，不比较列名；行内列位置不重排。
- 浮点数四舍五入至8位，整数与浮点数保留不同类型标签。
- 两条查询返回相同的空结果时可判定正确，不证明SQL语义等价。
- 只读SQLite执行，超过50000行视为执行失败。
- 超时沿用5秒SQLite进度回调机制，不是进程级硬超时。
- 畸形UTF-8使用替换解码。

## 故障处理

先执行参考SQL，再执行预测SQL。
保留历史正确性和可执行性标志的更新顺序。
新增evaluation_error_type，避免仅有零分而无法区分评估异常。

该字段是诊断扩展，不代表历史返回字典完全一致。

## 验证范围

提取函数源码与原文件对应片段一致，新增临时SQLite测试。
未验证真实历史轨迹端到端一致性，未验证完整V10字段兼容。
工具过程指标及训练奖励适配器尚待接入。

正式报告应区分参考SQL/环境异常与模型错误，并单独披露异常数量；
是否调整历史指标口径须作为独立变更，不能在迁移中静默修改。
