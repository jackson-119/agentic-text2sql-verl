# 正确性门控奖励

## 模块职责

`compose_reward(metrics)` 只负责奖励组合，不负责SQL提取、数据库执行、
结果相等判断或工具轨迹解析。

它来自实际训练使用的V10组合公式，迁移时保留数值行为。
历史v10_*和v3_*指标键暂时保留，避免同时改变接口与计算语义；
这些键不代表新仓库按历史版本组织。

## 分支优先级

1. 最终执行错误：固定-0.10，过程奖励及重复惩罚均为0。
2. 执行正确但协议非法：0.80。
3. 执行正确且符合过程奖励资格：0.98 + 过程加分 - 重复惩罚，
   再裁剪至[0.96, 1.00]。
4. 其他执行正确情况：0.90，包括直接回答、非严格格式等fallback。

过程资格同时要求严格格式、识别到答案、调用工具、协议有效、
无畸形调用且未在工具错误后停止。

五个过程指标等权，总加分最多0.02。
重复调用按次数每次扣0.005，总扣分最多0.02。

[0.96, 1.00]是代码允许的边界；不表示每种合成指标组合
都能由真实轨迹产生。旧源码注释中的0.98–1.00不能完整描述惩罚分支。

## 验证范围

- 与源组合函数进行16,384组合输入对照。
- 独立检查分支、过程加分、重复惩罚、fallback及输入不变性。
- 对照验证的是纯函数迁移，不是原始执行评估器正确性。
- 尚未接入SQL指标提取或完整训练Reward Manager。

## 未迁入的历史依赖

历史训练入口仍通过V8、V5、V4等模块获得指标。
新仓库后续将按SQL提取、执行比较、轨迹指标职责整理公共评估器，
在真实轨迹回放等价验证前，不替换服务器上的训练奖励。
