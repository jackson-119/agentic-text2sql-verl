# 累计过程回报

## 计算方式

终局奖励在同一prompt组内中心化，广播到所有有效assistant token。
过程奖励先按执行正确性与实际存在轮次进行门控，再沿轮次反向累计：
G(i,t) = sum(r_process(i,u), u >= t)，gamma=1。
token优势为终局相对优势加过程系数乘G，再加本轮格式项。

过程项不做跨轨迹中心化或标准差归一化。
终局标准差归一化是可选接口，历史默认关闭。
格式项仍局限在当前轮次，不累计；默认裁掉正格式奖励。
正确性门控仅应用于过程项，核心不门控格式项。
历史事件映射版本的格式向量为零。

## 迁移与输入契约

核心从本地实验工程逐字迁入，仅模块路径改变。
源码顶部旧概述仍称过程信号局部；实际实现是反向累计，
以函数实现、本说明和测试为准。

response_mask应为二值；分数应为有限浮点值，各输入设备应兼容。
显式turn_ids应为非负整数，动作位置使用对应的正轮次编号，
工具与padding位置为零，奖励向量必须覆盖所引用的轮次。
历史核心未完整校验所有非法输入，不能当作通用防御式API。

默认轮次推断依据mask连续动作区段。
相邻assistant轮次之间若没有零mask隔开，会被视为同一轮；
它不是可靠的通用Agent事件边界恢复器。
缺失轮次的过程奖励在累计前排除。
调用方应显式提供execution_correct；省略时回退为terminal_scores > 0。

轮次值在该轮全部token上广播，没有按轮次长度分摊。
因此最终优化影响仍受token长度与loss聚合方式影响。
未迁入事件奖励生成器和在线Reward Manager接线。

## 历史结果

Pilot200：128步、4096条rollout；Step0为44.0%，
开发集选择Step72为52.5%。同集选模，不能将其视为独立测试收益。

Selection417：原始V10 Step88为225/417（53.96%），
累计回报Step72为216/417（51.80%），差值约-2.16个百分点。
配对95%区间约[-5.28, 0.96]个百分点，McNemar p约0.233。
未观察到优于原始V10的证据，也不能据此证明两者等效。

Selection417被反复作为开发集使用。
该比较是不同方法最佳候选比较，不是仅改变奖励分配的严格消融。
历史结果来自原训练环境，本次迁移没有重跑实验或训练。
